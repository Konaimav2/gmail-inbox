Overview

Cookie-based multi-Gmail inbox. Local fetch of mail.google.com with saved sessions, 30-day history, realtime new-mail push (only for the selected account), cloud-mail compatible envelope.

Base URL __BASE_URL__
Envelope { "code": 200, "message": "success", "data": ... }
Realtime SSE on /api/sse — events: update new

API key vs public token — what each is for

API key (mh_live_…, 72 chars)Public token (32 chars)
PurposeFull, privileged access to every endpoint (list accounts, read any mail, refresh, rotate). Your private master credential.Read-only access to just the public endpoints (/api/public/emailList). Lets you fetch mail into your own app without exposing write/management powers.
Routes/api/accounts, /api/email/list, /api/email/latest, /api/allEmail/list, /api/sse, /api/rotate/api/public/emailList only
HeaderAuthorization: <API_KEY> or X-API-Key: <API_KEY>Authorization: <PUBLIC_TOKEN>
Reveal on docsEye toggle (hidden by default) + rotate buttonEye toggle (hidden by default)
Share it?⚠️ Never — treat like a password. Anyone with it can read every inbox.Safe to embed in your own client/app if it only needs to list mail.
Use case: keep the API key secret for your own server-side scripts. If you're building a public-facing widget or a read-only client, issue/use the public token so a leak can't be escalated into a full account takeover.
Native routes (/api/accounts, /api/sse, /api/select) require X-API-Key or a page session. Cloud routes (/api/email/*, /api/account/*, /api/public/*) use Authorization: <key> (no Bearer prefix).

Endpoints

POST/loginauth: password
Page login — returns API key + public token, sets the gsess session cookie (7 days, restart-proof HMAC).
Request 
curl -X POST __BASE_URL__/login -H "Content-Type: application/json" \
  -d '{"password":"YOUR_PAGE_PASSWORD"}'
Response 200 
{ "apiKey": "__API_KEY__", "publicToken": "__PUBLIC_TOKEN__" }
Errors
401 bad password · 429 blocked (5 min after 20 fails/60s)

Search the inbox across all accounts. Public endpoint — use the public token.
curl -X POST __BASE_URL__/api/public/emailList \
  -H "Authorization: <PUBLIC_TOKEN>" -H "Content-Type: application/json" \
  -d '{"size":3}'

POST/api/email/listauth: full (API key)
Cloud-mail email list, optionally scoped to one account. Use the API key.
curl -X POST __BASE_URL__/api/email/list \
  -H "Authorization: <API_KEY>" -H "Content-Type: application/json" \
  -d '{"size":3,"accountEmail":"you@gmail.com"}'
Response (example, dummy data) 
{ "code": 200, "message": "success", "data": [
  { "emailId": 1, "subject": "Welcome to Acme", "toEmail": "you@gmail.com" } ] }
GET/api/sseauth: full (X-API-Key or session)
Realtime event stream. Only the selected account is polled (set via /api/select on the app). Event types: update (thread list refreshed), new (new mail detected, payload {email, unread, ts}).
curl -N -H "X-API-Key: <YOUR_API_KEY>" __BASE_URL__/api/sse
Stream (example) 
event: update
data: {"ts":1787249110549}
POST/api/rotateauth: full (current X-API-Key or session)
Rotate the API key. Generates a new key, stores it in the local DB, and returns it. The old key stops working immediately.
curl -X POST __BASE_URL__/api/rotate -H "X-API-Key: <YOUR_API_KEY>"
Response (example) 
{ "code": 200, "message": "success", "data": { "apiKey": "mh_live_<new random 64-hex>" } }

Limits & retention

  • History: 30 days per account (newer_than:30d), stored in SQLite.
  • Full sync every 5h (SYNC_MINUTES=300) for all accounts — keeps Google sessions active.
  • Realtime atom poll every 120s — selected account only.
  • Request body cap 1 MB; rate limit 20 failed auths/60s per IP.
  • Cookies persist as JSON (never logged, gitignored); dead sessions auto-quarantine to cookies/invalid/.
